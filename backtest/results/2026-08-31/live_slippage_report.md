# 결론 (한 줄)

**실측 라운드트립 체결비용은 중앙값 4.61bps로 백테스트 taker 가정(11.0bps)보다 오히려 낮고**, 이 비용을 반영해 홀드아웃(2025-01-01~2026-08-28)을 재실행하면 net **+34.29%(중앙값 케이스)**, 최악 관측 케이스도 **+19.67%**로 — 양쪽 다 뚜렷한 순이익이다. `holdout_reverification.md` §2.3이 열어둔 "체결이 나쁘면 순손실(taker+15bps → −1.6%)"이라는 비관 시나리오는, **지금까지 실측된 실제 체결 품질(중앙값 5.07bps, 최악 10.04bps 슬리피지)로는 발생하지 않는다.**

⚠️ **표본 N=12(6 라운드트립)는 작다.** 통계적 검정이 아니라 관측값 나열로만 취급할 것 — 아래 §4.

# 1. 방법

`orders` 테이블(체결 SSOT — `trades` 테이블은 0행, 사용하지 않음)에서 `status='filled'` 주문을 `supertrend_signals`에 `bar_ts = date_trunc('4h', created_at) − 4h`로 조인해, 지정가 결정 근거가 된 신호봉 종가(`signal_price`) 대비 실제 체결가(`filled_price`)의 괴리를 측정했다.

```
slip_bps = sign × (filled_price − signal_price) / signal_price × 10⁴     sign = +1(buy) / −1(sell)
fee_bps  = fee / (filled_qty × filled_price) × 10⁴
```

분석 대상: `strategy_id='supertrend-01'`, 2026-07-01 이후 limit 체결 **12건(6 라운드트립)**. `manual-test-01` 3건과 2026-05-20~27 런칭 셰이크다운 3건(market 폴백 포함)은 별도 부록으로 분리(§5) — 코드/설정이 아직 안정화되지 않았던 초기 운영 구간이라 정상 운영 슬리피지와 혼합하지 않음.

# 4. 표본 크기 주의

N=12(6 라운드트립)는 통계적 분포 추정에 명백히 부족하다. 위 수치는 **점추정치로만** 취급해야 하며, 신뢰구간·유의성 검정은 시도하지 않았다. 체결 빈도(현재 페이스 월 ~2건)를 고려하면 표본이 30건대에 이르는 데는 1년 이상 걸린다 — 계획서(§A.4)가 "10건 누적 또는 분기 1회" 재실행을 권고한 이유다. 이번 실측은 "지금까지는 나쁘지 않다"는 확인이지, "앞으로도 나쁘지 않을 것"이라는 보장이 아니다.

# 5. 정합 감사 (§A.2) — 라이브 vs 정본 리플레이

## 5.1 (a) 2026-08-19 16:00 청산 → 08-20 00:00 재진입 — 원인 규명 완료: **버그 아님. 당시 배포된 구(舊) ATR 익절 규칙의 정상 동작**

> **정정 고지 (2026-08-31 후속 조사)**: 이 절의 초판은 이 청산을 "라이브 내부 이상 — `self._entry_price`가 실제 체결가와 괴리됐을 가능성이 유력"으로 기록했다. **그 결론은 틀렸다.** 후속 조사에서 근본 원인이 확정됐고, 진입가는 전 구간 정상(64,153.5)이었다. 아래는 정정된 내용이다.

**증상**: 라이브는 2026-08-17 진입 포지션을 08-19 16:00(신호봉 `bar_ts=12:00`)에 `exit_reason='atr_distance'`로 청산했으나, 정본 리플레이는 같은 구간에서 청산하지 않고 08-28까지 보유한다.

**근본 원인**: 그 시점 라이브에 배포돼 있던 코드의 ATR 청산 조건은 **상하 대칭(익절 겸 손절)** 이었다:

```python
atr_distance_exit = abs(price - self._entry_price) >= atr_stop   # 2026-08-20 이전 (구)
atr_distance_exit = price <= self._entry_price - atr_stop        # 현재 (익절 제거, 하방 전용)
```

구 규칙으로 검산하면 정확히 성립한다 — `|68,523.3 − 64,153.5| = 4,369.8 ≥ ATR(759.5588)×3.3 = 2,506.5` → **True**. 즉 이 청산은 **ATR 익절이 정상 발동**한 것이다. 반면 현재 규칙으로는 `68,523.3 > 64,153.5 − 2,506.5`이라 발동하지 않으며, **정본 리플레이 도구(`_replay_supertrend.py`)는 현재 규칙만 구현**하므로 2026-08-20 이전 거래에 대해서는 라이브와 리플레이가 **구조적으로 어긋나는 것이 정상**이다.

**왜 처음에 버그로 보였는가**: ATR 익절 제거는 **2026-08-20경 배포**됐으나 git 커밋은 **9일 뒤인 2026-08-29**(`2ee11756`)에 이뤄졌다. 08-19 시점의 git 트리를 보면 이미 구 코드가 커밋돼 있지 않아, "당시 실행 중이던 코드"를 git 히스토리만으로 재구성하면 잘못된 결론에 도달한다. 초판이 정확히 그 함정에 빠졌다.

**배포 시점 특정 (3중 독립 증거)**:

| # | 증거 | 결과 |
|---|---|---|
| 1 | 신호 대수 검산 | 08-19 12:00봉: 구 규칙 True / 현 규칙 False → 그 시점 **구 코드** 실행 중 |
| 2 | 신호 계산 지연의 위상·드리프트 | 봉당 드리프트가 **+4.95초 → +3.95초**로 영구 변경, 08-19 20:00봉에서 −22.2초 불연속(60초 랩어라운드 아님) → 전략 프로세스 재시작 창 = **2026-08-19 20:00:53 ~ 08-20 00:00:31 UTC** |
| 3 | 구 규칙 리플레이 전수 재현 | 구 규칙으로 리플레이하면 문제의 청산(`08-17 16:00 → 08-19 16:00 atr_distance`)과 `08-20 00:00` 재진입이 **시각·사유까지 정확히 재현**됨. 반대로 08-20 이후 라이브의 보유 행태(대형 상승 중 미청산)는 **현 규칙과만** 일치 |

08-20 이후 라이브가 계속 보유한 50개 봉은 전부 구 규칙이라면 익절 발동했어야 하는 구간인데 발동하지 않았다 — 재시작 창 이후 현 규칙이 적용됐음을 역으로 확증한다.

**결론**: 진입가 괴리 없음, 라이브 버그 없음, 조치 불필요. `self._entry_price`는 `positions` 테이블 기록(64,153.50)과 일치했고 `_sync_position_from_exchange()`도 정상 동작했다. 초판이 권고했던 "진입가 드리프트 로깅 추가"는 이 사건을 근거로는 정당화되지 않는다(방어적 개선으로서의 가치는 별개이며, 이 보고서는 더 이상 근거로 인용될 수 없다).

**남은 시사점 (실제 조치 대상)**: 문제는 코드가 아니라 **배포-커밋 간극(9일)** 이다. 이 기간 동안 git 트리는 라이브 상태를 반영하지 않았고, 그 결과 사후 조사가 존재하지 않는 버그를 추적하는 데 소요됐다. 전략 로직 변경은 배포와 커밋을 같은 작업 단위로 묶는 것이 재발 방지책이다.

**부수 확인 — 잔여 불일치 1건**: 리플레이는 라이브에 없는 1봉 왕복(2026-07-24 04:00 진입 → 12:00 청산)을 한 건 추가로 갖는다. 이 봉의 라이브 기록은 `st_dir=-1`(하락 국면 → 진입 불가), 리플레이는 `+1`이다. EMA 조건은 양쪽 다 충족(fast 65,353.48 vs slow 65,347.31 — 격차 $6)이며 Supertrend 방향만 갈렸다. Supertrend는 밴드 교차가 상태를 래치하는 경로의존 지표라 **CSV↔`ohlcv_history` 가격 드리프트($15~53, `csv_ohlcv_drift.md`)로 뒤집히기에 충분**하다 — ATR 규칙 변경과는 무관한 별개의 데이터 이슈로 분류한다.

## 5.2 (b) 2026-08-29 08:19:17 청산 지연(+19분) — 원인: 정상 운영 지연 (이상 아님)

해당 시각 전후 `orders` 테이블에는 **주문 1건뿐**(id=33) — 재호가(체이스)로 여러 주문이 순차 생성된 흔적 없음. `kill_switch_events` 0행 — Kill Switch/수동 `/kill` 개입 아님. `supertrend_signals`를 보면 이 청산 신호가 속한 04:00 봉(마감 08:00)의 **`computed_at`이 08:10:28**로, 신호 계산 자체가 봉 마감 후 10분 지연됐고, 이후 지정가 주문이 체결되기까지 추가로 ~9분이 걸려(체결 08:19:36) 총 +19분이 됐다.

**결론**: 재호가 남발도 수동 개입도 아니고, **신호 계산 지연(+10분) + post-only 지정가의 자연 체결 대기(+9분)**의 조합 — 정상 운영 범위의 지연으로 판단된다. 계산 지연의 근본 원인(스케줄링 주기·시장데이터 수신 지연 등)은 이번 조사 범위 밖.
