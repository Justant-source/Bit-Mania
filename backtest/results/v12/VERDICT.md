# Phase 2 — 1,536 격자 (완료)

```json
{ "st_factor":[2.0,2.2,2.4,2.6,2.8,3.0], "st_period":[6,8,10,12],
  "fast_ema":[4,6,8,10], "slow_ema":[24,27,30,33], "dir_ema":[180,220,260,300], "atr_mult":[3.3] }
```

## 하드 제약 결과

| 제약 | 임계값 | 통과 |
|---|---|---|
| C1 MDD | ≥ −66.697% (`#7908`) | 80/1,536 |
| C2 양수 블록 | ≥ 10/15 (64%) | 1,120/1,536 |
| C3 거래 수 | ≥ 120 | 1,536/1,536 |
| **C1∩C2∩C3** | | **56/1,536** |
| **C4 (이웃 통과비율 ≥0.7)** | | **0/56** — **최대 관측 비율 0.625** |

**MDD가 유일한 실질적 필터다** (C2·C3는 거의 모든 combo가 통과). `#7908`의 MDD는 전체 격자 1,536개 중 **94.8 백분위**(상위 5.2%) — 이 파라미터군에서 이미 강한 위험 지점에 있다.

## 왜 plateau가 없는가 — 진단

56개 통과 combo 중 **거의 전부가 `dir_ema=220` 단일값에 몰려 있다.** dir_ema별 MDD 중앙값:

| dir_ema | MDD 중앙값 (fast_ema≤6 부분집합) |
|---|---:|
| 180 | −81.8% |
| **220** | **−68.7%** |
| 260 | −71.9% |
| 300 | −77.0% |

`dir_ema≈220`이 넓게(384개 combo 평균) MDD를 개선하는 **실재하는 구조적 경향**임은 분명하다 — 이건 노이즈가 아니다. 그러나 `#7908`의 정확한 MDD 수치(−66.697%)를 **넘는** 것은 이 경향의 꼬리(`fast_ema≤6`이면서 나머지 축도 맞아떨어지는 조합)에서만 가능하고, 그 꼬리 안에서도 인접 격자값으로 한 칸만 움직이면(`fast_ema` 4→6, `dir_ema` 220→180/260) MDD가 4~18%p씩 나빠진다 — **knife-edge**. 계획서 §0.2 D2가 정확히 이 패턴("고립된 점, overfitting 의심")을 막기 위해 설계됐다.

예시(최고 `S_raw` 통과 combo, 격자 경계라 이웃 6개뿐):

```
중심: st_factor=2.0 st_period=12 fast_ema=4 slow_ema=33 dir_ema=220  → MDD=-64.55%
  fast_ema 4→6(같은 dir_ema=220): MDD -70.66% (C1 실패)
  dir_ema 220→180(같은 나머지):   MDD -82.38% (C1 실패)
  dir_ema 220→260(같은 나머지):   MDD -73.31% (C1 실패)
```

# 적대적 코드 감사 (2 병렬 에이전트)

NO_PLATEAU 결론의 신뢰도를 굳히기 위해, 자체 재검토에서 이미 하나의 불일치(§아래)를 발견한 뒤, 시뮬레이션 엔진과 통계 파이프라인 전체를 독립적으로 감사했다.

## 감사 1 — 엔진 (`_replay_supertrend.py`)

8개 항목(룩어헤드·이중청산·안전스탑 상호작용·`next_open` 생명주기·warmup/start 경계·수수료 이중계산·`stop_price` 잔존·캐시 안전성) 중 **7개 PASS**, **1개 버그**:

- `fill="next_open"` 모드에서 대기 체결이 `end_ms`/`start_ms` 경계에서 조용히 소실 — 정본 실행 시 거래 3건·최종 잔고 11.5% 누락. **`fill="close"`(Phase 2가 실제로 사용한 유일한 경로)는 영향 없음.**
- **수정 완료**: 대기 체결 실행을 경계 검사보다 먼저 처리하도록 재배치. 회귀 재검증 PASS.

## 감사 2 — 통계 파이프라인 (`replay_lib.py`/`apply_plateau.py` vs `PREREGISTRATION.md`)

블록 경계·기준선 수치·격자·C1–C3·점수함수·이웃 인접성 **전부 PASS**. **1개 불일치**(자체 재검토에서 먼저 발견한 것과 동일):

- `apply_plateau.py`가 C4에 사전등록되지 않은 절대개수 조건(이웃 ≥8)을 비율(≥0.7) 조건과 함께 추가 — 사전등록보다 **더 엄격**.
- 파케이 파일에서 **완전히 독립적으로 재구현한 코드**로 재확인: 사전등록 그대로(비율만)도 **56개 중 0개**, 최대 비율 0.625. **결론 불변.**
- **수정 완료**: 절대개수 조건 제거, `apply_plateau.py` 재실행 → 동일 결과.

**결론은 두 번의 독립 경로(제 자체 재구현 + 감사 에이전트의 별도 재구현)로 재확인됐다.**

# 왜 G1–G9와 Phase 4를 실행하지 않았는가

계획서(§0.1, §8.1)와 사전등록(§9)이 명시한 규칙: **plateau가 없으면 검증 배터리는 실행하지 않는다.** 이유는 두 가지다:

1. **검증할 대상이 없다.** G1(PBO)·G2(Walk-Forward)·G4(부트스트랩 귀무)는 전부 "선별 절차가 고른 특정 combo/영역"의 강건성을 확인하는 절차다. 절차가 아무것도 고르지 못했다면 확인할 것이 없다.
2. **여기서 더 파는 것 자체가 과적합 행위다.** knife-edge 위의 56개 점 중 하나를 억지로 "후보"로 승격시켜 G1–G9를 돌리는 것은, 사용자가 정확히 우려한 "과거엔 통했지만 미래엔 안 통하는 combo"를 찾아내는 결과로 이어질 위험이 크다. 사전등록된 중단 규칙을 지키는 것 자체가 이번 요청의 핵심 요구사항이다.

# 참고 — 노출은 됐으나 확정 후보 아님 (향후 v13 후보, 미실행)

`dir_ema≈200–220 & fast_ema≤6` 방향의 MDD 개선 경향은 **1) v11a(Jesse 엔진, 다른 격자)에서 fast_ema 저값 방향의 이점, 2) phaseA replay 분석(603 표본)에서 fast_ema 5–6 구간 우위, 3) 이번 v12 1,536격자에서 dir_ema=220의 광범위한 MDD 개선**까지 **세 번 독립적으로** 나타났다. 이는 노이즈로 치부하기엔 아깝지만, 지금 격자(step 40 in dir_ema, step 2 in fast_ema)로는 이 경향이 "넓은 분지"인지 "여전히 좁은 능선"인지 구분할 해상도가 없다.

**이것을 지금 추가로 파고들지 않는다.** 사전등록 이후 "유망해 보이는 방향을 봤으니 더 세밀하게 보자"는 판단 자체가 과적합 경로의 전형(사전등록의 존재 이유)이기 때문이다. 원한다면 **완전히 새로운 사전등록**(다른 세션, 다른 결과 확인 시점)으로 `dir_ema∈[190,250] step 10, fast_ema∈{4,5,6,7} step 1` 미세격자를 v13으로 독립 실행할 수 있다 — 이번 v12의 연장이 아니라 별도 가설 검정으로.
