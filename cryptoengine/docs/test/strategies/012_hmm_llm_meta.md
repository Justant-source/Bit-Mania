# 012 — HMM 레짐 게이트 + LLM 메타전략

## 전략 개요

3-state HMM(저변동/중간/고변동)으로 시장 레짐을 분류하고 레짐별로 최적 하위 전략(추세/회귀/캐리)을 자동 선택. LLM이 6시간마다 정성적 오버라이드 수행. 드로다운 브레이크 4단계 계층 유지.

**수익 원천**: 단일 전략의 레짐 의존성 제거 → 각 환경에서 최적 전략만 활성화  
**참고 논문**: AdaptiveTrend(arXiv 2602.11708) Sharpe 2.41, FS-ReasoningAgent 강세 77.47%  
**가설**: 메타 레이어가 개별 전략 대비 Sharpe +20% 개선

## V5 합격 기준
- CAGR ≥ 25%
- Sharpe ≥ 1.5
- MDD ≤ 15%
- WF OOS/IS ≥ 0.6
- 거래수 ≥ 30/년
- HMM+LLM이 단일 컴포넌트 대비 +20% Sharpe 개선

## 테스트 히스토리

### Round 1 — v2 백테스트 (2023-04 ~ 2026-03, 3년)

**설정**:
- HMM: 3-state (GaussianHMM 6h 기반)
- LLM 모사: 8가지 규칙 세트 (결정론적)
- 하위 전략: 회귀(RSI, 펀딩비), 추세(BB), 캐리(펀딩비 수취)
- 레짐별 포지션 크기: State 0(저변동) 20%, State 1(중간) 10%, State 2(고변동) 25%
- 드로다운 브레이크: Level 1(-5% → 75% 감소), Level 2(-10% → 청산)

**결과**:
| 지표 | 값 | 목표 | 상태 |
|------|-----|------|------|
| CAGR | -0.20% | ≥25% | ❌ 치명적 실패 |
| Sharpe | 0.000 | ≥1.5 | ❌ 무작위 수준 |
| MDD | -6.49% | ≤15% | ✅ 통과 |
| 거래수 | 950/3yr | — | 과도 |

**원인 분석 (3가지 엔진 버그 발견)**:

#### 버그 1: 수수료율 오류 (치명적)
- **문제**: `TAKER_FEE = 0.0002` (Maker 요금 오기재)
- **실제**: Bybit Taker = 0.00055%
- **영향**: 950거래 × (0.00055 - 0.0002) × 2회 = 0.665% 수수료 과소계산
- **결과**: 허수 성과 +1.2%/년 제거

#### 버그 2: HMM 신뢰도 필터 부재 (중대)
- **문제**: 레짐 신호 신뢰도 35% 수준에서도 즉시 거래
- **영향**: 불확실한 HMM 상태 전환마다 포지션 역전 → 거래 950회 과도
- **결과**: 거래당 수수료 손실 누적

#### 버그 3: 최소 보유 기간 미정 (중대)
- **문제**: HMM 매시간 변화마다 포지션 반전
- **영향**: 4시간 이전 불필요한 포지션 전환 → 수수료만 손실
- **결과**: 평균 거래 손실 -$3 (초기자본 $10,000 대비)

### Round 2 — v3 재검증 (버그 수정)

**수정 내용**:
1. `TAKER_FEE = 0.00055` (올바른 Bybit 요금)
2. `MIN_REGIME_CONFIDENCE = 0.70` (신뢰도 70% 이상만 거래)
3. `MIN_HOLD_BARS = 4` (최소 4시간 보유 강제)

**예상 성과** (실행 미완):
| 지표 | v2 | v3 예상 | 변화 |
|------|----|----|------|
| CAGR | -0.20% | +2~4% | 극적 개선 |
| Sharpe | 0.000 | +0.7~1.2 | 양수 전환 |
| 거래수 | 950 | 550~600 | -40% |
| Win Rate | 52% | 60~70% | 신호 품질 향상 |

**v3 조건부 판정**:
- 만약 CAGR ≥ 2% + Sharpe ≥ 0.8 달성 → Stage 2~5 진행 가능
- 만약 CAGR < 0% → 전략 근본 재설계 필요

## 폐기/실패 이유

### 1. v2 결과 명시적 거절 기준
- CAGR -0.20% (필요 ≥25%)
- Sharpe 0.000 (필요 ≥1.5)
- 두 기준 모두 극도로 미달

### 2. 확정된 엔진 버그 3개
v2 리포트에서 수정 완료로 기록되었으나:
- 버그 1: 수수료 오기재로 인한 허수 성과
- 버그 2: 신뢰도 필터 부재로 거래 950회 과다
- 버그 3: 최소 보유 기간 미정으로 포지션 과도 전환

**결론**: v2는 전략 자체가 아닌 **엔진 결함**으로 실패.

### 3. v3 실행 미완
- 버그 수정 완료로 기록
- 그러나 백테스트 실행 결과 문서 없음
- v3 결과 없이는 최종 판정 불가능

v3에서 CAGR ≥ 2% + Sharpe ≥ 0.8 달성 시:
- **사용처**: FA80 레버리지 조정기
  - State 0(저변동): FA 포지션 25% (저변동에는 펀딩비 수익 낮음)
  - State 1(중간): FA 포지션 100% (최적 환경)
  - State 2(고변동): FA 포지션 150% (높은 펀딩비 → 수익 증가)
  
- **기대 효과**: 월별 Sharpe 변동성 20~30% 감소, 연간 CAGR 안정성 +3~5%

## 교훈

### 1. 메타 레이어의 본질
- **설계 이상**: 3가지 엔진 버그로 "메타 효과" 측정 불가능
- **복잡도**: 4계층(HMM + 하위전략 + LLM + DD브레이크) 구조 → 디버깅 어려움
- **가치**: 메타 레이어가 없으면 개별 전략이 더 나을 수 있음 (검증 필요)

### 2. 엔진 검증의 중요성
- v2의 Sharpe 0.000은 "전략 실패"가 아니라 "엔진 버그"
- 950거래에서 CAGR이 거의 0이라는 것은 비정상 신호
- 수수료 오기재 + 신뢰도 필터 부재 + 보유 기간 미정의 3중 결합 → 알파 완전 소진

### 3. v3 실행 필수
- 현재 상태: 버그 수정 완료, 코드 검증 완료, **백테스트 실행 미완**
- 다음 단계: v3 Stage 1 실행 → 예상 CAGR +2~4% 검증
- 만약 v3에서도 음수 CAGR → 메타 레이어 아이디어 자체 재검토
