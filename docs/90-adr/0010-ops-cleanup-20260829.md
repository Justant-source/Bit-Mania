# ADR-0010. 2026-08-29 운영 창에서 확정·적용한 변경

## Status

Accepted (2026-08-29). 라이브 Phase 5(Bybit 메인넷, Supertrend 4h)에서 **같은 날** 적용했다. 코드·문서 정본 커밋은 히스토리 재작성 후 `9f5b116f`(원격 `origin/main`과 동일).

선행 코드 정리(21개 전략 소스 삭제)는 ADR-0009 / 커밋 `8a341ea2`(구 `16c64166`). 이 ADR은 **그 다음 운영 창**에서 한 DB·자격증명·킬스위치·배포 관례를 고정한다.

---

## Context

2026-08-29 오후에 다음이 겹쳤다.

1. **실전 청산 누락**: Redis/market-data가 낮에 재시작된 뒤 execution-engine·supertrend는 구 pub/sub 소켓을 붙잡고 있었다. 17:00 KST(UTC 08:00) 4h 종가에서 EMA 데드크로스가 났지만 `order:request` 구독자가 0이라 지정가 청산이 나가지 않았다. 워치독 지정가 이후 재시도로 **17:19 KST** 시장 경로로 청산(0.007 BTC). 포지션은 이후 플랫.
2. **레거시 DB**: `quarterly_perp_spread` 한 테이블이 ~8.9GB로 라이브 DB(~9.4GB)의 대부분을 차지했고, collector가 매일 write-only로 계속 쌓고 있었다. SELECT 하는 앱 코드는 없었다.
3. **마이그레이션 이중 트랙**: Alembic head는 `007_quarterly_futures`에서 멈춤. 운영 스키마는 raw SQL `017`까지. 신규 환경이 운영과 불일치.
4. **공개 저장소 평문 자격증명**: Redis/Postgres/Jesse/Grafana 예시 비밀번호가 히스토리에 존재. Bybit API 키는 `.env`(gitignore)에만 있어 노출되지 않음. 백테스트 PG 5433이 `0.0.0.0` 바인딩.
5. **수동 킬스위치 공백**: `ce:kill_switch`에 구독자가 없어 Telegram `/emergency_close`가 신규 주문만 막고 포지션은 남겼다. `make emergency`는 없는 모듈을 호출해 실패.

실행 창 규칙: Supertrend는 **확정 4h 종가**에서만 신호를 평가한다. 종가 직후 ~3시간 50분이 재시작 여유. dead-man은 **execution-engine 프로세스 다운 5분**(하트비트 TTL 300s)이지 Postgres 정지 시간과 다르다.

## 운영 관례 (이 날 확정)

### 배포 순서 — Supertrend를 오케스트레이터보다 먼저

`tick_interval: 60`. 전략은 루프당 한 번만 `pubsub.get_message`를 비운 뒤 60초 sleep 한다. 오케스트레이터가 먼저 뜨면 `start`가 구독 전에 발행되어 **한 틱(최대 60초) 동안 `is_running=false`** 가 된다. 권장:

1. `docker compose build` (다운타임 없이 이미지부터)
2. `up -d --no-deps` market-data, execution-engine, telegram-bot, **supertrend**
3. 잠시 후 **strategy-orchestrator**
4. `command_received` / `strategy_started` / `ohlcv_subscription_started` 확인

### Docker Compose와 셸 env

**에이전트/SSH 세션에서 `source cryptoengine/.env` 하지 말 것.** Compose는 이미 export된 셸 변수를 파일보다 우선한다. 로테이션 직후 옛 비밀번호가 셸에 남아 EE가 Postgres `InvalidPasswordError`를 낼 수 있다. `unset DB_PASSWORD REDIS_PASSWORD REDIS_URL` 후 compose가 `.env` 파일을 읽게 한다.

### 4h 봉 시각

`ohlcv_history.timestamp` = **봉 시작(open time)**. UTC 08:00에 마감된 봉의 행은 **04:00 UTC**. 형성 중인 봉(08:00–12:00 UTC)은 Redis `cache:ohlcv:bybit:BTCUSDT:4h` / `/candles/in-progress`. collector 기동 백필은 “한 봉 갭”을 진행 중 봉으로 보고 건너뛴다 — 확정봉 누락이 아니다.

신호 평가: **확정 종가 직후** (~마감+15s). ST 빨간 선만으로는 청산하지 않음. 청산은 EMA7&lt;EMA29 또는 ATR 손절.

### 잔고 게이트 (2026-08-29 청산 후)

청산 체결 후 Bybit 지갑 `total` ≈ **238.88 USDT**. `cache:wallet_balance`와 오케스트레이터 할당이 이 값과 맞다. `.env` `EXPECTED_INITIAL_BALANCE_USD` 폴백도 **238.88**로 현행화(파일은 gitignore). Phase 5 개시 당시 $185.31, 중간 $181.99는 **역사적 스냅샷**이지 현재 게이트 값이 아니다.

### 자격증명

런타임 비밀은 `cryptoengine/.env` · `dashboard/.env` · `backtest/docker/.env`만. 코드는 `require_env()` / compose `${:?}`. 로그 URL은 `redact_url()`. Redis CLI는 `-a "$REDIS_PASSWORD"` (컨테이너에 비밀번호 env가 없을 수 있음 — 호스트 `.env`를 서브셸에서만 source).

히스토리 재작성은 **노출을 되돌리지 않는다.** 실질 방어는 로테이션(D8)이다. 클론은 재작성 이후 다시 받아야 한다.

## Consequences

- 라이브 DB가 ~306MB로 줄어 백업·VACUUM·디스크 압력이 완화됐다. 분기물 적재가 멈춰 재성장하지 않는다.
- 신규 DB 부트스트랩은 `001`–`018` raw SQL과 운영이 같다 (ADR-0006 갭 해소).
- 수동 킬스위치는 오케스트레이터가 듣는 한 동작한다. L4 MANUAL은 auto-resume 불가 — 테스트 발동 후 `ce:kill_switch:active` 삭제 및 프로세스 재생성으로 인메모리 상태를 Cleared.
- 공개 히스토리에서 옛 비밀번호 문자열은 `***REMOVED***`. GitHub force-push 후 옛 객체는 한동안 원격에 남을 수 있다. 저장소 private + Secret Scanning을 권고한다 (`gh`는 작업 호스트에 없음).
- 롤백: 코드는 태그 `legacy-archive-2026-08-29`(`2ee11756`) — **재작성 전 레거시 소스가 되살아남**. DB는 D1 tar / 논리 백업(`legacy-cleanup-20260829_cryptoengine.sql.gz`, pg-backup 볼륨 7일 만료 ~2026-09-05). 재작성 전 전체 번들: `~/bitmania-pre-rewrite-20260829.bundle`.
